막힌 곳 찾기고객이 들어오고, 사고, 다시 오는 과정 중 어디서 끊기는지 숫자로 확인합니다.

지금 팀이 겪는 문제와 비슷한 사례부터 보셔도 됩니다. 각 사례 끝에 제가 합류하면 무엇부터 할지 적어두었습니다.

CASE 01 · 그로스 건강검진 시트 — 어디가 막혔는지 찾기설계·구현 직접

어디서 매출이 새는지 모른다면

상황고객사 대부분이 광고, 쇼핑몰, GA4 숫자를 따로 보고 있어서 무엇부터 고칠지를 의견으로 정하고 있었습니다. 엑셀로 된 진단표가 있었지만 계산 오류가 있었고, 채점과 리포트를 매번 사람이 만들어야 했습니다.

판단고객이 들어오고, 사고, 다시 오는 과정 전체를 같은 기준의 점수로 매겨야 우선순위를 숫자로 정할 수 있다고 봤습니다.

실행진단표를 83문항, 1,000점 만점, 기초체력 3영역과 핵심 7영역으로 다시 짜고 지표 28개를 정의했습니다. 구글 시트와 Apps Script, Claude API로 옮겨 응답지 배포·회수, AI 채점 초안, 고객사 제출본 생성까지 자동으로 돌아가게 했고, 기존 계산 오류 6건을 고쳤습니다.

진단 결과와 수치는 고객사 계약상 공개하지 않습니다.

배운 점같은 기준의 점수가 있어야 "무엇부터 고칠지"를 감이 아니라 숫자로 합의할 수 있습니다.

합류하면가장 먼저 지금 팀의 숫자로 어디가 막혀 있는지 정리하고, 무엇부터 고칠지 순서를 정합니다.

CASE 02 · 그로스 진단 템플릿 — 팀의 진단 방식을 같은 결과가 나오는 도구로설계 직접 · AI로 구현

좋은 진단 컨셉을, 매번 같은 숫자가 나오는 도구로

상황팀에는 고객사 진단 컨셉과 AI로 빠르게 만드는 분석 문서가 있었습니다. 다만 문서마다 정리 방식이 달라, 한 고객사의 문서 9건을 대조해 보니 같은 지표가 다르게 적힌 곳을 포함해 맞춰야 할 부분이 8건 나왔고, 고객사가 바뀌면 분석 틀과 용어도 조금씩 달라졌습니다.

판단진단 컨셉과 AI의 속도는 그대로 살리고, 계산과 검수만 코드로 고정하면 누가 언제 돌려도 같은 결과가 나온다고 봤습니다. 그리고 고객사가 받는 첫 장에는 분석보다 할 일이 있어야 한다고 봤습니다.

실행

  • 팀의 진단 항목을 퍼널 5단계, 지표 정의서, 판정 규칙 11개로 정리하고, 고객사마다 바뀌는 값은 설정 파일 하나(기간·객단가·공헌이익률 등)에 모음. 매장 예약형 브랜드와 온라인 커머스도 같은 계산 방식을 씀
  • 광고 관리자·쇼핑몰 주문·GA4 원본을 넣으면 지표 계산, 측정 점검, 진단 문서 5종, 자동 검수까지 한 번에 돌아가게 구현. 문서 속 숫자를 손으로 고치면 검수에서 걸림
  • 첫 장에는 지금 상태 한 문장, 핵심 숫자, 할 일 3개(누가·언제까지·어떤 숫자를 얼마로)만 담고, 빈칸이 있으면 내보내지 않음
  • 실제 커머스 고객사의 광고 원본으로 검증하며 하루치 광고비 누락 같은 데이터 문제를 찾아, 다음부터 자동으로 잡히는 점검 규칙으로 추가
찾아낸 것 · 실데이터 검증
검증한 광고 원본약 2.4만 행
하루 누락으로 빠진 광고비4.3%
따로 다시 계산한 값과 차이0원

이 과정에서 진단의 첫 질문을 "성과가 좋은가"에서 "받은 데이터가 전체인가"로 바꾸고, 측정 점검을 지표 계산 앞에 뒀습니다.

배운 점분석이 빨라질수록, 숫자를 검수하는 장치가 먼저 있어야 합니다.

합류하면팀에 이미 있는 분석 방식과 AI 활용은 살리고, 숫자의 출처와 검수 기준을 고정해 실행으로 이어지게 만듭니다.

CASE 03 · 아하모먼트 발굴 워크플로우 — 다시 사게 만드는 행동 찾기설계·구현 직접

다시 사게 만드는 첫 경험을 모른다면

상황고객사마다 다시 사는 고객이 처음에 무엇을 샀고 어떤 행동을 했는지 감으로 판단하고 있었습니다. 분석을 해도 매번 사람이 며칠씩 데이터를 정리해야 했고, 결과가 CRM 캠페인으로 이어지지 않는 경우가 많았습니다.

판단주문 데이터만 넣으면 같은 기준으로 돌아가는 도구로 만들기로 했습니다. 숫자는 코드가 계산하고, AI는 컬럼 정리·상품 분류·리포트 초안만 맡기고, 확정은 사람이 하도록 나눴습니다.

실행

  • 분석 지표 23종을 쇼핑몰 데이터로 뽑을 수 있는지 확인해 16개가 가능함을 확인하고, 우선순위대로 9개를 구현
  • 구매 주기, 입문 상품, 첫 구매 후 90일 LTV, 함께 사는 조합 등을 계산하고, 재구매율이 평균의 2배 이상인 행동을 '유력' 가설로 판정
  • 결과가 대표 보고용 리포트와 리토스 발송 조건 초안으로 바로 이어지게 연결
  • 실제 주문 수천 건으로 검증하며 계산 방식 7건을 고침
찾아낸 것 · 고객사 분석 예시
유제품 · 1→2회 구매 전환25.4%
같은 쇼핑몰 · 2→3회 구매 전환48.2%
구독형 브랜드 · 구독 전환 고객 LTV8.9배

두 번째 구매만 넘기면 다시 살 확률이 크게 오르는 구조라, 두 번째 구매를 아하모먼트로 정의했습니다. 분석 결과는 가설이며, 매출 효과는 캠페인 운영 후 확인합니다.

배운 점AI에는 정리와 초안만 맡기고, 숫자는 코드가, 확정은 사람이 해야 결과를 믿을 수 있습니다.

합류하면고객이 왜 다시 오는지 모르는 팀이라면, 다시 사게 만드는 첫 경험부터 데이터로 찾아 CRM 조건으로 바로 연결합니다.

CASE 04 · 유제품 쇼핑몰 (2024.06~10, 컨설팅·운영 대행)

광고를 늘려도 광고 밖 매출이 그대로라면

상황월 마케팅 예산 대부분을 Meta에, 그것도 할인 프로모션 때 몰아서 쓰고 있었고, 하루 매출은 30만 원대에 머물러 있었습니다. 목표는 온라인 매출 3배였습니다.

판단광고를 키우되, 광고로 처음 알게 된 고객이 다음에는 검색, 직접 방문, 채널 메시지로 다시 사도록 이어 줘야 광고비가 늘어난 만큼 매출이 쌓인다고 봤습니다.

실행

  • 네이버 검색광고를 키워드 유형(브랜드·경쟁사·업종·문장형) 단위로 다시 짜고, 브랜드검색 랜딩과 소재를 A/B 테스트
  • 가입 혜택과 쿠폰팩 3종으로 자사몰 가입과 첫 구매를 유도
  • 카카오 친구톡·문자를 신규 가입, 첫 구매, 재구매, 장바구니, 쿠폰 보유 고객별로 요일 고정 스케줄로 운영
  • Google·카카오모먼트·당근까지 매체를 넓혀 테스트하고, 통합 대시보드에서 매일 확인

같은 기간 하루 광고비도 3.7배(12만→44만 원) 늘었습니다. 광고비가 3.7배 느는 동안 광고 밖 매출이 2.4배 함께 늘어난 것이 이 사례의 핵심입니다.

배운 점광고·가입·메시지를 따로 개선하면 각각의 숫자는 좋아져도 매출로 쌓이지 않습니다.

합류하면광고를 늘려야 하는 팀이라면, 광고로 들어온 고객이 다음엔 광고 없이 다시 사도록 검색·가입·메시지 흐름부터 같이 짭니다.

CASE 05 · 소형가전 브랜드 (2025.05~08, 스마트스토어 중심)

광고 화면의 ROAS만 믿고 예산을 쓰고 있다면

상황네이버 GFA 광고를 광고 화면에 뜨는 ROAS만 보고 운영하고 있었습니다. 같은 달 광고 화면 ROAS는 3,527%(전환 추적 30일, 기존 구매자 포함)였고, 스마트스토어에 광고로 들어온 고객의 실제 매출로 계산하면 289%였습니다. 기준에 따라 12배 차이가 나는데, 예산을 어느 숫자로 판단할지 정해진 기준이 없었습니다.

판단예산 판단은 스마트스토어 실제 매출 기준으로 통일하고, 광고 화면 숫자는 소재·타깃끼리 비교할 때만 쓰기로 했습니다. ROAS가 높아도 구매가 몇 건 안 되는 그룹은 걸러냈습니다.

실행

  • 구매자 제외, 전환 추적 기간 30일 → 7일, 주말 새벽 노출 제한, 전환 0건 그룹 정리로 운영부터 정리
  • 광고를 단일 품목과 묶음·부속품으로 나눠 비교해, 묶음·부속품 쪽 ROAS가 464~524%로 단일 품목(0~392%)보다 꾸준히 높은 것을 확인하고 광고 구조를 재편, 부속품 캠페인 신설
  • 구매 이력 고객 세그먼트를 광고 타깃으로 써서 전환율 18.2%(전체 1.59%의 11배)를 확인하고, 문구·이미지·CTA를 나눠 소재 A/B 테스트
  • 소재·그룹 평가 기준을 ROAS 단독에서 'ROAS × 구매 수'로 바꿈
결과 · 착수 첫 달(5월) → 이후 2개월(6~7월) 평균, 스마트스토어 실제 매출 기준
